# Accessibility audit, November 24, 2026

The remediation landed in commit `3088010`. This report records the audit at that revision. Use the [living accessibility guide](../design/accessibility.md) for current requirements and verification.

Drevan targets WCAG 2.2 Level AA. This review started from clean commit `fdb88d2` and used the real Express routes, EJS views, assets, and catalog with disposable SQLite databases. The audit covers the public account pages, The Quarters, Nexaris, Dominion and its training report, Sanctum, Curious Emporium, The Reliquary, The Registry and player profiles, The Driftwater, The Ruins, Admin, and shared errors. The Bounty Board is a roadmap item with no current route or interface.

## Standards and evidence

- WCAG 2.2 is the normative accessibility target. Its Understanding documents, techniques, and evaluation guidance inform testing. WCAG 3.0 is a Working Draft. [WCAG 2.2](https://www.w3.org/TR/WCAG22/) · [Understanding WCAG](https://www.w3.org/WAI/WCAG22/Understanding/) · [Techniques](https://www.w3.org/WAI/WCAG22/Techniques/) · [Evaluation guidance](https://www.w3.org/WAI/test-evaluate/) · [WCAG 3.0](https://www.w3.org/TR/wcag-3.0/)
- HTML follows the Living Standard. WAI-ARIA 1.2 and ARIA in HTML are W3C Recommendations, and WAI-ARIA 1.3 is a Working Draft. APG examples are advisory. Nu checks HTML authoring requirements. [HTML](https://html.spec.whatwg.org/) · [WAI-ARIA 1.2](https://www.w3.org/TR/wai-aria/) · [WAI-ARIA 1.3](https://www.w3.org/TR/wai-aria-1.3/) · [ARIA in HTML](https://www.w3.org/TR/html-aria/) · [APG](https://www.w3.org/WAI/ARIA/apg/) · [Nu HTML Checker](https://validator.w3.org/nu/)
- One primary heading, descriptive surface names, and keeping result summaries close to actions are Drevan conventions. A 44 CSS pixel pointer target is an AAA enhancement. Shared controls use the AA target size or applicable spacing and inline exceptions to preserve the compact layout.

## ARIA and native semantics inventory

| Attribute or role               | Current uses and review                                                                                                                                                                                                                                                                                                                                |
| ------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |

| `aria-invalid`                  | Identifies affected signup inputs after server or browser validation. Native controls retain their built-in validation.                                                                                                                                                                                                                                |
| `aria-hidden`                   | Hides redundant map glyphs drawn in noninteractive squares. The marker disclosure exposes meaningful nonadjacent marker text. Focusable descendants were excluded from this treatment.                                                                                                                                                                 |
| `aria-live` and `role="status"` | Current totals can be queried on labeled output elements. Cart validation messages are polite status updates, and server-rendered feedback uses ordinary text and contextual focus.                                                                                                                                                                    |

The inventory table and cells use native semantics.                                                                                                                                                        |

The review found no custom tabs, toggle buttons, grid, modal dialogs, or live combat history requiring additional ARIA state. HTML validation covered the sampled server-rendered markup, and browser tests exercised interactive behavior and names. Screen reader output still requires platform testing.

## Verified measurements and scope

- Baseline axe-core 4.14.1 found zero rule violations across 18 standard-color Chromium snapshots. It marked color contrast for manual review and flagged map label matching for review. The visible single-letter tile markers are symbols with expanded names. The test treats forced-color mode separately because axe reported a large set of text contrast failures while combining system text with authored backgrounds in Chromium emulation.
- Baseline Nu reported 14 errors in the captured standard-color HTML. Five were resource meter value overrides and nine were inventory table role overrides. The updated Nu 26.11.20 run reported zero errors across 28 captured documents. Validation uses server-generated HTML before browser parsing or JavaScript mutations.
- Contrast sampled from the CSS and composited state colors. Gold text on the background is 5.77:1 and on the surface 5.00:1. Muted text on the surface is 5.45:1, red 4.91:1, and blue 7.47:1. Dark button text on gold is 5.77:1. The light Ruins movement glyph against the tinted tile is about 9.0:1, and sampled gold, green, and muted move borders exceed 3:1 against it. These measurements cover the listed pairs, with a visual review still needed for all interactive and overridden states.
- At 320 CSS pixels the baseline and audited snapshots fit the page viewport. Wide data tables scroll locally. Chrome keyboard checks verify the skip link moves focus to main, a table scrolls using Arrow Right, the map restores focus to the player square, and Tab can reach another legal move. Before the update, Tab from the same map position moved to a potion action.
- On macOS 26.7.3 with Node 26.13.1, Chromium 158.0.8127.38 and axe-core 4.14.1 reported zero violations across 28 standard-color snapshots. The browser suite covers signup, logout, credential failure and login, inventory filtering and equipment changes, a purchase and sale, stat allocation, potion use, Sanctum healing, training, a cast, map entry and movement, native movement with JavaScript disabled, and Recall. Existing HTTP integration tests exercise progression, equipment and item use, selling, healing, fishing exhaustion, expedition failures and encounters, and transactional outcomes. Playwright checks use Chromium and an isolated database. No VoiceOver, NVDA, TalkBack, Safari, Firefox, real touch device, or native browser zoom session was exercised. A narrow viewport is a reflow check and emulated media is a display-mode check. Neither reproduces every aspect of browser zoom or system settings.
